# 中转站介绍

## 什么是中转站

AI 中转站是连接用户与模型服务商的统一 API 网关。应用、脚本或 AI 编程工具先把请求发送到中转站，中转站完成身份验证、模型与端点检查、计费和渠道路由后，再将请求转发给可用的上游服务，并把结果返回给用户。

```text
客户端或应用 -> All Token API -> 可用的上游渠道 -> AI 模型
```

中转站本身不是 AI 模型，也不会替用户决定模型能力。接入一个兼容客户端通常需要三项信息：

- **API Key**：验证身份、限定访问范围并记录用量。
- **Base URL**：客户端向本站发送请求的服务地址。
- **模型 ID**：指定本次请求使用的模型，必须与模型广场或模型列表接口返回的名称一致。

本站还提供模型广场、API Key 管理、分组路由、实时健康状态、余额与充值、使用日志以及工具接入文档，用户可以在同一个控制台内完成配置、调用和排查。

## 为什么会有中转站

不同模型服务商的账号体系、接口地址、协议和计费方式并不相同。直接接入多个服务商时，往往需要分别注册账号、保存多套密钥、适配多种请求格式，并自行处理模型切换。

中转站主要简化以下工作：

- **统一服务入口**：通过一个站点管理不同提供商的模型。
- **减少客户端改动**：兼容常见 API 协议的客户端通常只需替换 API Key、Base URL 和模型 ID。
- **集中管理权限**：可按设备、应用或项目创建不同 API Key，并限制额度、有效期、模型、IP 和路由分组。
- **集中查看消费**：在使用日志中核对请求、Token、分组、计费详情和最终费用。
- **提高路由灵活性**：一个 API Key 可使用单个分组、系统路由或按顺序配置的多个候选分组，并可按需开启失败后的跨组重试。

> 中转站统一的是接入和管理方式，不代表每个模型都支持全部协议，也不能保证上游服务永远可用。实际能力以当前 API Key 可见的模型、模型详情中的端点类型和实时请求结果为准。

## 本中转站特色与优势

### 首页与模型广场

[首页](https://alltokenapi.com/)提供常用入口、模型与价格预览；[模型广场](https://alltokenapi.com/pricing)提供完整的可用模型目录。用户可以按模型名称、提供商、定价分组、标签、计费类型和端点类型进行筛选，并切换币种、Token 单位、排序方式和展示视图。

打开某个模型的详情后，可以进一步查看：

- 准确的模型 ID、提供商和模型说明；
- Token 计费或按次计费方式，以及输入、输出、缓存、媒体等适用价格；
- 各个可用分组的价格和动态定价规则；
- 当前模型支持的 API 端点、请求示例和参数说明；
- 已有监控数据时的延迟与可用率。

模型名称相近不代表端点和价格相同。正式调用前应复制准确的模型 ID，并阅读[模型定价与消耗](./模型定价与消耗.md)。

### API Key 与访问范围

在 [API Key 页面](https://alltokenapi.com/keys)可以创建、搜索、启用、禁用和删除密钥，并查看密钥状态、已用与剩余额度、创建时间、最近使用时间和过期时间。

创建或编辑 API Key 时，可以按使用场景配置：

- 有效期和独立额度；
- 允许调用的模型；
- 允许访问的 IP；
- 单个分组、系统路由，或有明确优先顺序的多个候选分组；
- 多分组模式下是否允许失败后继续尝试下一个分组。

API Key 页面还提供模型可用性测试。测试会先读取该密钥实际可见的模型，再根据模型声明的端点类型发送一个简短请求，并返回所用端点和响应时间。这个结果用于判断当前密钥与模型能否完成一次真实请求，不代表长期稳定性。

`GET /v1/models` 返回的是**当前 API Key 实际可用的模型**，结果会受到密钥的分组、模型限制和路由配置影响。不同密钥看到的模型列表可能不同，不应使用账号级模型目录替代该接口结果。

### 多协议 API

本站不仅提供 OpenAI Chat Completions，还提供多种协议入口。当前主要接口包括：

| 协议或能力 | 典型端点 |
| --- | --- |
| OpenAI 模型列表 | `GET /v1/models` |
| OpenAI Chat Completions | `POST /v1/chat/completions` |
| OpenAI Responses | `POST /v1/responses` |
| Anthropic Messages | `POST /v1/messages` |
| Gemini 原生接口 | `POST /v1beta/models/{model}:generateContent` |
| Embeddings | `POST /v1/embeddings` |
| 图像、音频、重排和视频 | 使用模型详情中显示的对应端点 |
| OpenAI Realtime | `GET /v1/realtime`，使用 WebSocket |

路由存在不等于任意模型都能使用该路由。应以模型广场显示的**端点类型**为准；例如 Claude 模型是否能用于 Responses API，取决于实际渠道能力和当前路由配置，不能只根据模型名称判断。

完整请求格式与示例请查看 [API 模型接口](../API集成/API模型接口.md)。

### 分组路由与实时健康

分组用于区分可用渠道和计费规则。为 API Key 选择多个候选分组时，系统会按配置顺序寻找可用能力；只有开启跨组重试后，请求失败时才会继续尝试后续分组。最终使用的分组和费用可以在使用日志中核对。

[分组状态](https://alltokenapi.com/group-status)页面展示当前公开监控分组的：

- 当前运行状态和最近一次请求延迟；
- 最近 7 天或 30 天的可用率；
- 最近 30 次监控结果与下次检查时间；
- 当前允许手动测试时的一次即时健康检查。

分组状态反映监控请求的实时健康和历史稳定性，不等同于“当前 API Key 已获得该分组权限”，也不代表分组内所有模型都支持同一种协议。选择模型时仍需同时检查密钥权限、模型支持和端点类型。

### 使用日志与问题排查

[使用日志](https://alltokenapi.com/usage-logs)分为常规请求、绘图任务和异步任务等类别。普通用户可以查看自己的请求，并按时间、模型、API Key 名称、分组、请求 ID 或任务 ID 进行筛选。

请求详情可用于核对：

- 请求状态、模型、端点和所用分组；
- 输入、输出、缓存、音频或图像等计费用量；
- 首字响应、总耗时等可用的性能数据；
- 最终扣费、退款和失败原因；
- 请求 ID，便于反馈问题时准确定位。

出现问题时，建议先记录请求时间、HTTP 状态码、模型 ID、端点和请求 ID，再到使用日志中查找对应记录。不要向他人提供完整 API Key。

### 钱包、充值与订阅

[钱包](https://alltokenapi.com/wallet)集中显示当前余额和站点已启用的资金入口。根据站点配置，页面可能提供在线充值、兑换码、订阅计划、账单历史和推荐奖励转入；未启用的功能不会显示。

订阅额度与钱包余额可能使用不同规则，支付方式、币种、手续费和最低金额也由当前站点配置决定。具体操作请查看[计费与支付](./计费与支付.md)。

### 文档与工具接入

本站文档提供 API 请求示例以及 CC Switch、Codex、Claude Code、Gemini CLI、OpenCode、OpenClaw 和 Hermes 等工具的接入说明。

API Key 页面支持通过 CC Switch 导入 Claude、Codex 和 Gemini 配置。导入时会根据目标工具处理服务地址，并只提供当前 API Key 路由范围内的模型供选择。详细步骤请查看 [CC Switch](../工具使用与接入/CC%20Switch.md)。

## Base URL 应该怎么填

不同客户端会自行追加不同的 API 路径，因此 Base URL 不能一概填写为同一个形式：

| 使用方式 | 建议地址 |
| --- | --- |
| OpenAI 兼容客户端 | `https://alltokenapi.com/v1` |
| Claude Code、Gemini CLI 等会自行追加协议路径的工具 | `https://alltokenapi.com` |
| 直接发送 HTTP 请求 | 使用服务根地址加文档规定的完整端点 |

如果工具接入文档给出了专用地址，应优先按照对应文档填写。常见的 `404` 原因是客户端已经自动追加 `/v1` 或 `/v1/messages`，用户又在 Base URL 中重复填写了相同路径。

## 推荐的开始顺序

1. [打开钱包](https://alltokenapi.com/wallet)，确认余额或订阅额度可用。
2. [查看模型广场](https://alltokenapi.com/pricing)，复制准确模型 ID，并确认价格、分组和端点类型。
3. [创建 API Key](https://alltokenapi.com/keys)，按应用设置额度、有效期、模型、IP 和分组限制。
4. 使用该 API Key 请求 `/v1/models`，确认目标模型确实可见。
5. 在 API Key 页面运行一次可用性测试，或按照 [API 模型接口](../API集成/API模型接口.md)发送一个简短请求。
6. 打开[使用日志](https://alltokenapi.com/usage-logs)，核对模型、端点、Token、分组和最终费用。
7. 正式接入时，继续阅读对应的 API 或工具文档，并为不同应用使用不同密钥。

> 请妥善保存 API Key，只在受信任的服务端、本地客户端私有配置文件或凭据存储中使用。不要把密钥写入公开代码、网页前端、截图或聊天记录。如果密钥可能已经泄露，请立即禁用或删除，并重新创建。
