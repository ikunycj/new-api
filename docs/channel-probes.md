# 渠道自动探测

启用渠道的“自动探测”后，master 节点通过一个持续运行的 `channel_probe` 系统任务推进探测周期。系统内部固定每 60 秒推进一次计数；渠道按 `probe_period_minutes` 的值分组，例如周期为 1、2、3 时，分别每 1、2、3 个系统周期触发一次。

- 同一探测周期组到期时，组内所有符合条件的渠道会同时异步启动，不设置调度器级并发上限，也不占用渠道的业务请求并发额度。
- 启用和自动禁用渠道使用同一个探测周期。`auto_disabled_probe_interval_seconds` 已移除，渠道进入自动禁用状态不会改变所属周期或单独提前调度。
- `probe_random_delay_enabled` 开启后，每个渠道在周期触发时会先随机等待 0 到 60 秒，再开始上游请求；这只分散请求起点，不改变周期计数。
- `probe_stream_enabled` 开启后使用流式请求验证上游。Codex 渠道因协议要求始终使用流式探测。
- 每个渠道最多一个探测在途，使用数据库租约协调 master 切换。随机延迟和上游请求都可随系统任务取消；单个上游探测及重试最多使用 240 秒，渠道租约为 360 秒。
- 路由策略只保留“自动探测”一个总开关。开启后探测失败自动禁用，已自动禁用的渠道在自动探测或手动单渠道、批量测试成功后恢复启用；手动禁用的渠道不会自动恢复。该闭环独立于业务请求的 `auto_ban` 和全局自动禁用配置，分组可用性监控不触发恢复。
- 自动探测的成功恢复、失败禁用、历史记录和租约释放在同一事务内提交。过期或已被替换的租约不能提交结果；执行期间关闭自动探测或手动禁用，以提交时的当前配置和状态为准。手动测试恢复不改动自动探测历史或租约。
- 多密钥渠道仅在本次成功使用的 Key 仍存在且可用时恢复渠道，不解除任何 Key 隔离。全部 Key 已被禁用时，需先解除具体 Key 的禁用。

升级迁移会把旧的 `probe_interval_seconds` 向上取整转换为分钟级 `probe_period_minutes`，删除 `auto_disabled_probe_interval_seconds` 和逐渠道 `next_probe_at` 调度字段。已有 `auto_probe_enabled` 设置保持不变。

`CHANNEL_PROBE_TASK_ENABLED=false` 关闭此任务。任务丢失系统租约会取消并等待在途请求退出；异常后的重建仍受系统任务扫描周期影响。持续任务每 15 秒更新计数，不使用完成百分比。修改部署环境变量需要重启实例。
