# 渠道级调度与监控策略

## 目标

每个渠道都是独立的健康、重试、自动禁用和熔断单元。全局自动禁用开关和全局关键词/状态码不参与运行时判定，避免一个上游的规则影响其他渠道。

## 调度顺序

```text
模型/分组能力过滤
 -> 人工禁用和自动禁用过滤
 -> 渠道熔断过滤
 -> 渠道并发过滤
 -> 动态健康评分（价格、可用性、负载）
 -> Weight 公平分流
 -> 当前渠道的独立重试预算
```

`channels.priority` 只保留用于旧数据和兼容读取，普通请求不会再按它建立硬优先级层。`weight` 是渠道唯一的静态流量分配参数；未配置或为 0 时使用默认权重。

## 渠道级规则

- `auto_ban`：允许该渠道在规则命中时进入自动禁用状态。
- `setting.auto_disable_status_codes`：逗号或换行分隔的状态码/范围，例如 `401,429,500-599`。
- `setting.auto_disable_keywords`：逗号或换行分隔的错误关键词。
- `setting.auto_disable_response_time_ms`：单渠道探测响应时延阈值，0 表示关闭。
- `upstream_max_retries`：当前渠道独立的最大尝试次数。
- `auto_probe_enabled`、探测间隔、自动恢复和 `max_concurrency`：均按渠道生效。

## 状态颜色

管理后台同时显示颜色、状态文字、原因和时间：绿色为正常（enabled），黄色为自动禁用（auto-disabled），红色为人工禁用（manually disabled）。颜色仅用于可视化，实际选路仍以状态和熔断检查为准。

## 兼容与迁移

旧的 Priority、force priority 和全局自动禁用配置不做破坏性删列。升级后新请求不读取这些字段；保留字段便于回滚和历史数据审计。确认稳定后再安排独立的数据清理。
